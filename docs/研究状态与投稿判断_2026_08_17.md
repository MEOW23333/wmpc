# 大规模电路仿真联合研究阶段总结与投稿决策

日期：2026 年 8 月 17 日  
代码分支：`hard_block_minimal_push`  
状态：预条件子稀疏部署已完成；联合论文证据链尚未闭合；实验计划已确认并记录。

## 一、当前结论

当前工作已经形成一个有明确技术贡献的研究原型，但还不能直接投稿“warmup 加学习型预条件子”的完整联合论文。

目前最可靠、可以经核验写入论文的主线是：

> 面向大规模电路仿真的预测初值与内存受限稀疏固定块 Schwarz 协同框架。

其中，warmup 负责减少非线性求解的 Newton 工作量；稀疏固定块 Schwarz 负责在不构造全局稠密矩阵的情况下改善线性子问题；当前 `learned_full` 只作为严格消融和反例，不能作为优于固定规则的主方法结论。

## 二、已经达到的效果

### 1. 稀疏预条件子精度与内存

在 full500 真实工作点上，阶段一结果为：

| 指标 | 已核验结果 |
| --- | ---: |
| 方程维数 | 1,704 |
| 非零元数 | 11,306 |
| 稠密与稀疏算子相对二范数误差 | `2.28116602572133e-33` |
| 预条件器增量常驻内存节省 | `58.4985%` |
| 整个隔离进程峰值常驻内存节省 | `7.3475%` |
| 保守结构峰值内存估算节省 | `96.6345%` |

因此，已经成立的准确表述是“预条件器增量内存实测节省超过 50%，且稀疏算子与稠密参考算子数值一致”。不能把 58.50% 写成整个仿真进程的内存节省。

另一批三规模稀疏验证共 60 个任务，严格成功 57/60：10×10 为 20/20，10×100 为 20/20，100×100 为 17/20。100×100 未收敛集中在电路 1、13、19；平均覆盖率约为 42.70%，因此这批结果证明了稀疏结构的跨规模可运行性，不证明当前学习参数已经跨规模泛化。

### 2. 固定块 Schwarz 的线性迭代收益

同一 20 个正 `gmin` 冻结工作点、同一 `rhsold` 初值、同一真实残差门槛下：

| 方案 | 严格成功 | 平均 GMRES 迭代 |
| --- | ---: | ---: |
| `row_sum` | 20/20 | 26.0 |
| `fixed_same_blocks` | 20/20 | 8.1 |
| `learned_overlap_weights_only` | 20/20 | 8.1 |
| `learned_shift_only` | 20/20 | 29.0 |
| `learned_full` | 20/20 | 29.0 |

固定块 Schwarz 将平均线性迭代减少约 68.8%，这是当前最清晰的求解器收益证据。但小矩阵的块构造成本约为 0.030 秒，已经覆盖求解阶段节省，所以当前不能宣称端到端时间加速。

### 3. 当前学习型参数的真实边界

当前检查点的学习移位在正 `gmin` 工作点上使迭代数升高，学习重叠权重与固定均分没有可观测差异。这个结果不是失败，而是一个有价值的负消融：它说明必须把移位约束、训练分布和规模适配作为独立研究问题，不能把“增加学习头”直接等同于“得到更好的预条件子”。

### 4. warmup 的证据边界

历史汇总曾出现平均减少约 3.72 次 Newton 迭代，但历史向量与当前 full500 网表不一致，且旧汇总存在按阶段序号配对、原生阶段记录缺失和模型溯源不足的问题。该数字只能作为历史线索，不能作为当前论文主结果。

当前新二进制已经加入输入长度守卫：旧线路 2 的 430 维向量配当前 240 维网表会被拒绝，11 个阶段均 `injected=0`。这证明了输入安全性和失败可见性，不证明 warmup 已减少 Newton 迭代。

## 三、已完成的实现与记录改进

1. 全局矩阵保持稀疏格式，局部块才转为小型稠密矩阵，并使用局部 LU 因子，不保存全局稠密逆矩阵。
2. 预条件子支持 `fixed_same_blocks`、`learned_shift_only`、`learned_overlap_weights_only`、`learned_full` 四种可审计参数模式。
3. 预处理入口默认禁止零提议模型回退，默认拒绝特征维度截断和补零；诊断用途必须显式传入 `--allow-zero-proposer` 或 `--allow-feature-adaptation`。
4. 预处理入口不再删除整个训练数据目录；覆盖已有输出必须显式传入 `--overwrite-output`。
5. 新增训练来源侧车模块 `pypath/aggregator/training_provenance.py`，记录原始轨迹、网表目录、proposer 检查点、代码、环境和输出文件指纹；教师训练诊断同时记录来源侧车状态。
6. 新增 `pypath/utils/generate_online_learned_schwarz_sidecars_batch.py`，在同一进程复用模型缓存，支持把在线侧车批量预生成。
7. 20 项预条件子单元测试全部通过；远程 `PALS_env` 解释器编译检查通过；`git diff --check` 通过。

## 四、后续实验计划与准入门槛

以下计划沿用已确认方案。任何训练、批量数据生成和大规模仿真都必须先写清输出指标，再启动执行。

### 阶段一：来源契约和冻结清单

- 固定 full500 原始轨迹、当前网表、节点映射、二进制、环境和代码指纹。
- 固定不可变的训练、验证、测试电路清单，建议使用 162/20/20 跨线路切分。
- 检查 proposer 检查点是否覆盖全部单元类型；缺失或维度不一致直接失败，不允许静默补零。
- 输出：来源侧车、切分清单、文件哈希、环境摘要、失败清单。

### 阶段二：重新生成双头数据并重训

- 在可见 GPU 的远程环境中重新生成 full500 双头数据。
- 训练 warmup 头和预条件子头，验证集选择检查点；至少使用 3 个训练随机种子。
- 记录样本数、有效标签比例、各 `gmin` 桶分布、训练/验证损失、检查点哈希和来源侧车哈希。
- 不使用当前历史检查点直接宣称泛化。

### 阶段三：冻结 warmup 双轨证据链

- 冻结阶段轨道：同一原生二进制、同一网表、同一环境、同一入口状态，只切换 warmup 注入。
- 在线轨道：按实际 Newton 阶段生成输入，记录阶段覆盖率、路径差异、回退原因和最终解一致性。
- 每个配对样本同时记录 Newton 次数、最终残差、KCL、最终解差异、注入状态和异常原因。
- 只有成功配对且最终解一致时，才统计 Newton 节省。

### 阶段四：预条件子独立测试

每个测试工作点分别运行以下方案：

1. `row_sum`；
2. `fixed_same_blocks`；
3. 内存匹配的 ILU 或块 Jacobi 强基线；
4. `learned_shift_only`；
5. `learned_overlap_weights_only`；
6. `learned_full`。

每个方案必须逐工作点记录：严格收敛、真实相对残差、GMRES 迭代、构造时间、求解时间、总时间、回退次数、预条件器增量峰值内存、线性阶段峰值内存和整进程峰值内存。内存指标必须分栏，不能混用。

### 阶段五：联合实验

先做小规模因果先导，再扩展到跨规模：

- 无 warmup + `row_sum`；
- 有 warmup + `row_sum`；
- 无 warmup + 固定块 Schwarz；
- 有 warmup + 固定块 Schwarz；
- 在同一四臂基础上增加已冻结的学习消融。

联合主表至少覆盖 10×10、10×100、100×100 三种规模，并报告成功率、Newton、GMRES、真实残差、最终解一致性、构造/求解/总时间、回退率和两种内存口径。

### 统一成功门槛

- 真实相对残差：`||Ax-b||₂ / max(||b||₂, ε) < 1e-8`；
- 无未记录的直接法回退、零提议回退或维度补齐；
- 最终解与基线在预先约定的相对误差门槛内一致；
- 学习模式在独立测试集上的成功率不低于固定块基线；
- 若要写“整个仿真进程内存节省超过 50%”，必须有配对的整进程峰值实测证据，不能使用结构估算替代。

## 六、2026 年 8 月 17 日联合冒烟核验

在历史 full500 网表与旧 warmup 输入上，运行器完成了四臂任务准备：12 个任务全部生成，网表、输入向量和在线侧车路径均有指纹；随后只运行线路 2 的两个 `row_sum` 臂：

| 臂 | 阶段收敛 | warmup 注入 | 总 Newton | 耗时 | 严格结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| `cold_row_sum` | 11/11 | 0 | 337 | 6.772 秒 | 因直接法回退拒绝 |
| `warm_row_sum` | 11/11 | 0 | 337 | 6.751 秒 | 因输入未注入拒绝 |
| `cold_learned_schwarz` | 未完成 | 0 | 未形成 | 约 260 秒后终止 | 在线侧车到第 13 个 Newton 步仍在生成，超过冒烟预算 |

该冒烟结果不是性能主表，但它完成了两个重要验证：

1. 运行器不会把直接法回退或未注入的 warmup 样本误记为成功；
2. 当前旧向量没有形成 warmup 因果对照，冷、热两臂 Newton 数完全相同，因此历史输入不能用于证明联合收益。
3. 当前在线学习侧车按 Newton 步逐次生成，单线路冒烟成本过高；该任务被记录为 `aborted_by_budget`，不计入性能汇总，也不能用作失败收敛率分母。

被终止的 `cold_learned_schwarz` 已留下 119 条原生指标：其中 27 条 GMRES 严格收敛、92 条触发直接法回退，回退率为 77.31%；累计在线侧车生成时间约 254.34 秒，平均每步约 2.14 秒；已观测块覆盖率约 94.17%，预条件器增量估算平均约 61 KiB。它说明稀疏 Schwarz 侧车本身能够生成并在部分工作点收敛，但当前“每个 Newton 步启动一个 Python 生成器”的部署路径不满足大规模仿真时间预算。

随后用同一批已捕获的 120 个线性系统工作点测试批量入口：单进程总耗时 2.896 秒，全部 120/120 成功；抽查 5 个工作点的矩阵指纹、布局指纹、向量指纹、块参数和字节数均与逐步生成侧车完全一致。按这批数据估算，批量预生成相对逐步启动生成器约减少两个数量级的启动开销，但它尚未接入原生四臂重跑，不能直接写成端到端加速。

对应产物：`pals_data/runs/joint_warmup_schwarz_preflight_20260817_full500_online/`。其中 `aggregate/summary.json` 只汇总已运行的 2 个任务；学习臂的 `manual_abort.json` 单独记录预算终止，另外 9 个任务保持缺失，不补零、不插值。
