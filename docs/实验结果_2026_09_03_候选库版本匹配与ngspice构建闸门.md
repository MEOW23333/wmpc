# 实验结果：候选工艺库版本匹配与 ngspice 构建闸门（2026-09-03）

## 结论

先前“服务器没有完整编译器”的结论不成立。系统默认的 `gcc` 和 `make` 软链接确有异常，但开发工具集 `/opt/rh/devtoolset-9/` 提供可用的 `gcc 9.3.1` 和 `make 4.2.1`。2026-09-04 已在独立目录 `build_devtoolset9_osdi_20260904/` 成功构建 `ngspice-44+`；配置中 `OSDI_WANTED_TRUE` 已启用，且生成了 `src/osdi/Makefile`。

使用该二进制执行 `pre_osdi`，成功加载官方 BSIM-CMG 111.2.1 的 OSDI 产物，并完成 GT2N `gt2_6t_inv_x1_w13_svt` 反相器的工作点求解：进程正常结束，`v(y)=5.731836e-07` 伏。二进制散列为 `479c75291cb24227aa7bc71af26360349d43b4ea637714b80976e901c679827e`，所加载模型散列为 `6d48b4fac4d909fc58e30764c19ad5f03cbe39b08bc1278240935ba3e840490e`，完整输出保存于 `results/candidates/devtoolset9_osdi_build_gate_20260904/official_bsimcmg111_load.txt`。启动时的 `spinit` 缺失警告未影响批处理工作点计算。

这证明当前 `wmpc` 源码可在该服务器用完整工具链构建，并且构建产物的 OSDI 外部模型加载路径可用。它不证明仿真器能直接解析 HSPICE `level=72` 或 Verilog-A `.hdl`；这两类模型仍须先编译为 OSDI，且单一工作点成功也不能证明 GT2N 的物理时序精度。

## 版本匹配测试现象

ASAP5 对应 BSIM-CMG 107、FreePDK3 对应 BSIM-CMG 108 的最小测试均未通过可用性闸门：原始示例网表使用的模型类型、器件实例参数和 OSDI 注册接口不一致，出现 `unknown parameter (tfin)`、`unknown subckt` 或模型无法找到等错误。即便修正这些语法问题，也必须重新核对 `DEVTYPE/TYPE`、几何参数和未声明模型参数，才能讨论数值或物理等价。

## 指标与失败原因

- 计划任务数：工具链构建及官方模型加载核验 1 项，版本模型诊断 2 项。
- 严格成功数：构建及官方模型加载核验 1/1；107/108 候选模型的最小网表仍未通过。
- 工作点：1/1 正常完成；单一工作点未导出方程维数、非零元、内存或迭代数，均不适用。
- 仍存在的失败原因：107/108 模型卡与 OSDI 接口不匹配；当前无 HSPICE 参考波形。

## 研究边界

本结果证明编译环境与 OSDI 加载接口不再是阻塞，但不能证明 ASAP5、FreePDK3、GT2N 或 GT3 模型本身错误，也不能证明与 HSPICE 的物理结果等价。后续应固定 OpenVAF、BSIM-CMG 版本、ngspice 提交号和模型卡散列，重跑 107/108 的最小网表与参考波形对照。
