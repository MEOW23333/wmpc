# 实验结果：PKP3 三纳米候选库闸门（2026-09-03）

## 结论

PKP3 是目前最值得保留的替代候选：公开仓库、BSD-3-Clause 许可、预测三纳米纳米片 GAAFET，模型为 PHIMO-Fusion，并提供标准单元、SRAM 和完整工艺文件。但在当前服务器上尚未接入 ngspice，原因是模型编译器和模拟器接口均存在阻塞。

## 已核验事实

- 仓库：`https://github.com/PHIMO-Group/PKP3.git`
- 固定提交：`9c38ccf3e2f5682ec7e859bcff9e41bde1e08996`
- 模型入口：`fusion_ic_nmos_lvt.va`、`fusion_ic_pmos_lvt.va`
- 模型族：PHIMO-Fusion，源自 BSIM-CMG 111.2.1，但不是 GT2N 所用的原始 BSIM-CMG 模型。
- 原始 `models/include.sp` 使用 `.hdl` 和商业仿真器风格的模型加载方式。

## 接口闸门

1. OpenVAF 23.5.0 直接编译：失败。报错包括自定义 `instance_parameter_list` 属性和常量表达式引用变量。
2. 派生语法适配后再编译：OpenVAF 在死代码优化阶段崩溃，生成越界错误；将优化级别降为 0 仍复现。
3. OpenVAF-reloaded 0.4：未能启动，预编译程序要求较新的 `GLIBC`，当前服务器为 `GLIBC 2.17`。
4. 直接把 Verilog-A 放入 ngspice：失败，当前 ngspice 报告 `.hdl` 命令未实现。

因此严格成功数为 0/3；没有进入有效工作点、直流或瞬态仿真，方程维数、内存、耗时和迭代数均不适用。

## 物理正确性边界

上述结果只能证明 PKP3 在当前工具链上的接入阻塞，不能证明模型本身错误，也不能证明其与 HSPICE、商业仿真器或原始作者结果等价。若要继续，应在具备完整编译器且 `GLIBC` 足够新的服务器上，用原始 PHIMO 模型编译 OSDI；若必须在旧服务器运行，则需从源码构建兼容版本的 OpenVAF，并对崩溃点建立最小复现。
