# 实验结果：PKP3 自建编译链闸门（2026-09-05）

## 结论

自建兼容工具链已成功构建并证明“Verilog-A 编译为 OSDI、再由 ngspice-44+ 加载”的通路可用；但未经改写的 PKP3 原始 NMOS 模型在语义分析阶段失败，未生成 OSDI。依照预先确认的停止条件，未改写模型，未继续 PMOS、单管、反相器或瞬态任务。PKP3 仍不能作为当前环境中的可用三纳米仿真库，更不能声称物理正确仿真。

## 固定输入与构建结果

- PKP3 固定提交为 `9c38ccf3e2f5682ec7e859bcff9e41bde1e08996`；原始 NMOS 文件为 `models/PHIMO/VERILOG-A/PHIMO_NMOS/fusion_ic_nmos_lvt.va`，散列为 `1410e0a2ff5252265508c5cf61cfca071a6b94dfdca7cdff7822f97f1ec93ed0`。
- OpenVAF-reloaded 固定提交为 `fdf2522b70f42793f64b1c72f0195c96dea0cc19`。为适配当前服务器的 `GLIBC 2.17`，在 `wmpc/.cache/pkp3_toolchain_20260905/` 内从源码构建；生成器散列为 `216f6f4e89c8040084045d173786dfef027d8cc5541a6334a132bb435ff0fd73`，动态依赖仅指向当前系统的 `librt`、`libdl`、`libpthread`、`libm`、`libstdc++`、`libgcc_s` 与 `libc`。
- 宿主工具为开发工具集的 `gcc 9.3.1`、`make 4.2.1` 和 `cmake 4.0.0-rc4`。LLVM 为 18.1.8，构建时启用 X86 与 AArch64 后端及 `clang`；后两项是 OpenVAF 构建脚本生成 x86 与 ARM64 Windows 运行时对象所必需，未修改系统软件。
- Rust 先后验证 1.83 与 1.85 均因当前依赖版本不足而失败，最终使用隔离的 1.90.0；解析后的依赖锁定文件散列为 `335d1ddefa3a8abfa270f32fa9d0227ba52be223f9847d98836901e7c63c3cde`。构建缓存最终占用 8.8 吉字节，低于 12 吉字节预算。

## 先决接口闸门

OpenVAF-reloaded 成功把其自带 BSIM-CMG 源码编译为 713 千字节 OSDI，产物散列为 `089d68822e29069ad9945ab7f7e5c8524474dbd14f8630788134014492540e91`。使用项目内 `ngspice-44+` 的控制块 `pre_osdi` 加载该产物，输出 `OSDI_LOAD_OK`，无加载致命错误。ngspice 二进制散列为 `479c75291cb24227aa7bc71af26360349d43b4ea637714b80976e901c679827e`。

这只证明自建生成器、OSDI 0.4 与当前 ngspice 的接口闭环可用，不证明 PKP3 模型可用，也不构成任何物理精度结论。

## PKP3 原始模型闸门

对原始 NMOS 直接执行 60 秒上限的编译。任务在约 3 秒内结束，严格成功数为 0/1，未超时，未产生 OSDI。六处错误均为“常量表达式不得引用变量”：第 479 至 482 行以 `MEL` 初始化 `mx`、`mxprime`、`md`、`mdprime`，第 595 行以 `EPSRSUB / EPSROX` 初始化 `epsratio`。完整日志位于隔离缓存的 `logs/pkp3_nmos_lvt_raw_compile.log`，散列为 `8b8201e457b550473959e8df5248fdd141b461246c73b2d0053238f5df2600b7`。

这是新版编译器的 Verilog-A 常量初始化语义限制；它不同于旧 OpenVAF 的死代码消除位集越界。两类失败都发生于电路求解之前，因此方程维数、非零元、内存、迭代数、残差、直流与瞬态结果均不适用。

## 处置与后续边界

未将前置变量内联为字面量，也未以过程赋值改写模型；这类改动虽然可能是语义等价的候选补丁，但未经模型作者或参考仿真器逐点验证，不能当作原始 PKP3 物理模型。下一条有效路线是取得作者认可的可移植 Verilog-A 版本，或在有商业参考仿真器的条件下对严格受控的语义等价移植做逐点校准。取得其中任一条件前，停止扩大 PKP3 测试。
